## 一、设计与证据标准

1. 先写清楚读者应理解的关键区别，再确定输入、操作、可观察结果，最后选择组件与技术栈。
2. 真实计算、真实轨迹回放、原文证据探索分开标注。回放必须记录模型、版本、配置、输入、输出及来源，不能冒充实时推理。
3. 替代模型只用于验证机制，不声称等同原论文模型和成绩。缺少可信模型输出或记录时保留待办，不用预设正确答案填充。
4. 数学、代码、结构图解释同一个案例；独立算子例子必须明确标识。3D 仅在空间结构、张量关系或路径确实受益时使用。
5. 原论文的实验设计、旧方法、方法提出过程、消融、失败与结论应围绕案例展开；不预设每篇都按统一六步顺序阅读。
6. 原生 PyTorch 教学代码保留。预训练模型库负责权重与模型适配，教学关键步骤仍显式展开，例如 DDPM 的每一步采样、CLIP 的归一化/相似度、ReAct 的执行循环。

## 二、22 篇各自的表达方式

| 论文 | 理解目标 | 主体验与所需证据 |
|---|---|---|
| ViT | patch 后的局部信息怎样参与全局判断 | 真实照片拆解台：切块、点选、遮挡/打乱，联动 token 与真实分类变化；再连接预训练规模实验。响应或注意力不可自动当作因果解释。 |
| DDPM | 逐步噪声预测如何形成生成；训练与生成的区别 | 两条图像时间轴：输入图片的正向加噪、已训练小模型从随机噪声生成的真实反向轨迹。暂停查看 ε̂、均值及下一步；训练视图独立显示随机 t 与损失。已知 ε 的还原仅为辅助。 |
| CLIP | 自然语言监督如何支持通过文字指定类别 | 真实图文检索桌面：图片与候选文字、描述改写、相似度排名；再展开训练时批内正负配对。展示误匹配；不用手工向量代替主实验。 |
| LLaVA | 视觉输入对回答有什么作用、哪里会误解 | 图片问答取证台：有图/无图/遮挡关键区域的真实输出对照；用户核查回答事实与图像依据。训练阶段用检查点或原文消融，接口图只作解释。 |
| SAM | 提示如何指定分割目标，单点歧义如何消除 | 真实分割画布：正负点、框、多个模型候选掩码；连续提示复用图像编码。几何区域筛选退为辅助，不充当模型输出。 |
| MMaDA | 文本/图像如何统一成离散去噪，怎样区别于 AR | 多模态生成分镜：真实或可追溯轨迹中，文本位置、掩码状态、图像码解码画面同步；解释多位置迭代恢复与逐词追加，以及三个训练阶段。 |
| AlphaGo | 策略直觉、价值与搜索为什么结合 | 合法棋盘与多层搜索回放：先猜落点，再逐次展开分支与对应棋局，比较搜索预算下的选择。需可信引擎/轨迹；根节点固定数值例子不能替代主实验。 |
| AlphaZero | 网络指导搜索、搜索产生监督的循环怎样改进 | 自我对弈成长档案：同一测试局面不同训练检查点的策略、搜索与落子；追踪一盘棋生成的 (s,π,z) 如何进入后续更新。小棋种替代实验明确与原文棋力区别。 |
| InstructGPT | 流畅与遵循指令为何不同，偏好如何介入 | 回答评审席：同题基础/SFT/偏好优化的真实回答，先盲评再揭示阶段；追踪偏好对形成奖励信号，纳入奖励高但仍有缺陷的样例。 |
| DeepSeek-R1 | 推理表现如何变化，组内奖励提供什么 | 固定题集的真实候选、验证结果、长度和成功率；追踪同题奖励与优势，分别呈现 R1-Zero 与 R1 路线。不把长答案当作能力提升的充分证据。 |
| GPT-1 | 预训练对下游学习有什么价值 | 相同小模型随机初始化/预训练后分类的真实学习曲线与错误样例；改变标签预算。共享主干和任务头辅助解释，不用“换头”代替迁移收益实验。 |
| BERT | 两侧上下文实际提供什么信息 | 上下文线索实验室：需后文消歧的句子，逐段开放左右文，观察真实 MLM 候选排序；对照单向可见范围，区分输入替换、预测目标、attention mask。 |
| GPT-2 | 同一续写模型怎样表现不同任务 | 续写编辑器：固定原文，更换续写/摘要/问答提示，记录真实输出与失败。模型与权重固定，任务线索作为文本进入上下文。 |
| GPT-3 | 示例如何不改权重却改变行为，有何不稳定性 | 上下文实验台：增减示例、调顺序、换标签、加入错误示例，比较真实输出。原 GPT-3 不可用时标明替代模型，不用规则答案宣称原模型能力。 |
| LLaMA | 小模型训练更充分为何有部署价值 | 模型取舍面板：任务成绩、参数、训练 token、可获得的实际内存/时延；按需求选方案。RoPE/RMSNorm/SwiGLU 放入结构细节，不单独代表整篇论文。 |
| CoT | 中间步骤何时有帮助，何时只是详细犯错 | 同题直接回答/CoT 提示下真实输出，核验最终答案与公开解答步骤，按题型、模型条件比较失败和成功。不是通过开关手写算式证明效果。 |
| ReAct | 外部观察怎样改变后续行动 | 可执行任务环境：同题对照不同方法的真实 Action/Observation 与公开任务记录；注入错误、资料失效等干预，检查重试、改查与证据。不是固定剧本，也不展示私有思维。 |
| Toolformer | 如何获得何时调用工具的训练信号 | 工具样本加工车间：真实文本候选调用、真实工具返回、同一小语言模型后续 token 的实际损失；读者筛选再核对规则，区分与 ReAct 的运行阶段。 |
| Scaling Laws | 如何由实验发现规律，拟合与外推何时失效 | 数据分析台：有来源的实验点，坐标切换、拟合区间选择、留出点预测与揭示。若仅有原图，区分图像读图/近似数字化与作者原始数据。合成曲线仅辅助。 |
| Chinchilla | 固定算力下模型与 token 怎样分配 | 算力预算沙盘：基于原文结果或明确有效范围内的拟合比较等算力配置和最优区域；不以自造对称公式预置正确答案。 |
| Mixtral | 总参数、活跃计算与路由模式有什么区别 | 专家调度台：可用模型的真实逐 token、逐层路由；整句/批次负载；重复词与不同语境对照，检查“领域专家”解释。资源不足时使用记录回放。 |
| GPT-4 报告 | 有限披露的报告支持哪些结论 | 证据审查桌面：能力声明—评测条件—样例—局限—原文页码互相连接；保留失败。不给未知精确架构绘制确定的 3D 图。 |

## 三、实施顺序与验收关口

### 首批三篇完整样板

1. **DDPM**：32×32 预训练小模型的实际无条件生成、每步记录、缓存回放与正向加噪对照。先证明“生成过程”可正确查看，不承诺高分辨率或任意照片编辑。
2. **CLIP**：真实图片/文字编码、相似度与检索排名、提示改写对照。首批 checkpoint 以英语文本为主，不能默认中文检索等效；中文扩展须单独选模型并标注。
3. **ReAct**：有实际模型决策的封闭任务环境，真实执行工具、保存反馈与证据、可重复故障干预。固定脚本仅用于测环境，不能作主模型轨迹。

三篇完成后由用户检查教学效果，再扩展其余 19 篇。此处是内容与交互验收关口，不是本轮安装/下载/部署授权。

### 每篇验收条件

- 不看论文标题也能认出这课在解释的现象；移除 3D 后不能只剩换皮数字表。
- 用户操作引起可核对的数据/输出变化，并能解释哪些变量固定、哪些变化。
- 同一案例可追踪到实际代码或记录来源；显示运行/回放/原文证据三种状态。
- 有至少一个失败、边界或反例，不安排“新方法永远更好”。
- 模型、checkpoint/revision、预处理、随机种子、采样/生成设置、输入及输出在记录中可查。
- 界面、数学与源论文论断一致；模型替代、图表数字化和未完成项都如实说明。

## 四、安装与部署方案

### 已有基础（本轮读取依赖清单，未导入包验证）

- 前端 Vue 3、TypeScript、Vite、Playwright；后端 FastAPI、Uvicorn、PyTorch、NumPy、Pillow、httpx。
- 不替换现有 CNN/ResNet 推理。新实验在独立适配层实现。
- 首批前端用现有 Vue + Canvas/SVG 足够；不为了“技术升级”统一引入 3D 引擎。

### 首批拟新增依赖

| 依赖/资源 | 用途 | 是否现在安装 |
|---|---|---|
| `transformers` | CLIP 模型及 tokenizer/processor；后续小型语言模型适配 | 待开发环境兼容性检查后安装并锁版本 |
| `diffusers` | DDPM 权重、UNet 与 scheduler 适配；显式展开采样记录 | 同上，不用一行 pipeline 隐藏教学步骤 |
| `huggingface_hub`、`safetensors` | 下载/缓存、模型 revision、权重读取 | 作为模型依赖一并锁定，可能由上两包间接安装 |
| `accelerate` | 后续设备映射/低内存加载 | 单设备显式 `.to(device)` 的首版不是硬性必需；按实际需要启用 |
| DDPM checkpoint `google/ddpm-cifar10-32` | 32×32 无条件生成 | 拟下载单一权重格式约 143 MB，加配置；不是文生图模型 |
| CLIP checkpoint `openai/clip-vit-base-patch32` | 图文编码与相似度 | 拟下载 PyTorch 权重约 605 MB，加 tokenizer/配置；不整仓下载多框架副本 |
| ReAct 的语言模型来源 | 真实选择行动与利用反馈 | API 或本地推理二选一，尚未选定，不默认要求云端上传 |

权重大小是仓库单文件体积，不是运行内存。两组主权重合计约 748 MB；建议为首批权重、下载缓存、依赖和帧记录预留 5–10 GB（规划余量，不是测得的占用）。

原环境依赖版本已有锁文件，不执行无约束全量升级。可以为实验 worker 使用独立虚拟环境，以免影响既有图片分类服务；最终兼容版本在获准运行依赖检查后锁定。本轮没有创建环境或修改锁文件。

### 服务拓扑（拟实现，尚未部署）

浏览器 Vue → 现有 FastAPI → 本机模型实验 worker → 模型缓存/实验轨迹目录。

- worker 按需加载模型，首版重型任务并发上限 1；长任务返回任务 ID，提供进度、取消、失败状态与轨迹回放。
- API 仍由现有后端提供；worker 可以是子进程，本机运行，不新增公网地址。
- 轨迹使用 JSON 元数据 + PNG/数值文件，定义保存与清理规则，不一次返回全部中间 tensor。
- 首批不需要数据库服务、Redis、Docker、Kubernetes 或云服务器；不要求训练基础模型或下载完整训练集。
- Mac/arm64 优先评估 PyTorch MPS，保留 CPU 路径。本轮未检查 MPS 可用性、内存容量和速度，不承诺实时 DDPM 生成。Mac 不安装 NVIDIA CUDA。
- ReAct 若用 API：配置 endpoint、模型名、服务端环境变量凭据与费用边界；若用本地模型：需先确认内存与模型大小，再确定推理运行方式。已有 httpx 可用于 HTTP 适配，无需先引入完整 Agent 框架。

### 后续按课引入

- `echarts`：实验点、误差条、对数坐标、预算对照；Scaling Laws/Chinchilla 阶段再引入。
- `konva` + `vue-konva`：复杂图片标注、拖拽框、分层画布；SAM/ViT 如原生 Canvas 交互不足再引入。
- SAM、语言模型、LLaVA 等各自权重与适配依赖按课确定。Mixtral/MMaDA/训练过程优先检查真实轨迹可得性及计算资源，不要求本机同时部署 22 个模型。
